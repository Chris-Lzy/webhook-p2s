# webhook-p2s — 拓竹打印机钉钉监控

轻量级拓竹（Bambu Lab）打印机局域网监控服务：通过打印机本地 MQTT 接口实时获取打印状态，将开始 / 完成 / 失败 / 暂停 / 进度等事件推送到钉钉群机器人。自带 Web 配置页，Docker 一键部署，无需注册云服务、数据不出局域网（推送除外）。

## 功能

- **多设备管理**：内置 20 个打印机席位，每个席位可单独「启动 / 停用 / 测试」，互不影响；推送标题自动带上设备名称，如「P2S_1 开始打印」
- **Web 配置页**：打印机名称 / IP / 序列号 / 访问码、钉钉 Webhook / 加签密钥 / 关键词，全部在页面上填写；密钥类配置脱敏显示、留空保持不变
- **实时状态**：每台设备独立显示打印进度条、层数、剩余时间、喷嘴 / 热床温度、任务文件名、已用时
- **摄像头画面**：推送时自动抓取对应打印机的 RTSP 流，快照图直接内嵌在钉钉消息中，并附带 N 秒短视频链接（2–15 秒可调）
- **事件推送（可按需勾选）**：开始打印 / 打印完成 / 打印失败 / 暂停 / 恢复 / 打印中离线 / 进度节点（每 N% 推一次）
- **推送时间段**：可添加多个时段，支持跨午夜（如 22:00–07:00）和按星期筛选；每个时段单独勾选要推送的事件。未添加任何时段时，与以前一样全天推送
- **连通性测试**：每行「测试」按钮校验该打印机的 MQTT 连接（可顺带抓取摄像头画面预览）；钉钉推送单独测试，且不受时间段限制
- **事件日志**：最近 50 条推送与连接事件；被时间段拦住的推送仍会记一笔「已跳过」
- **版本号**：页面标题旁显示当前版本（与 `app.py` 里的 `__version__` 一致，目前为 1.1.0）
- **Docker Compose 部署**：配置持久化到 `./data`，容器自动重启；默认时区 `Asia/Shanghai`

## 快速开始

```bash
git clone https://github.com/Chris-Lzy/webhook-p2s.git
cd webhook-p2s
docker compose up -d --build
```

浏览器打开 `http://NAS的IP:8787`，按页面提示填写配置即可。

## 配置说明

### 打印机（拓竹）

1. 打印机屏幕：**设置 → 局域网 / LAN 模式**，开启后页面会显示**访问码（Access Code）**
2. 序列号（SN）可在同一页面或「关于机器」中查看
3. 打印机与 NAS 需在同一局域网
4. 页面共 20 个席位，用到哪台就填哪台：填好名称 / IP / SN / 访问码后点「保存全部」，再点该行「启动」。停用只会断开该台设备的监控，不影响其他设备

### 钉钉群机器人

群设置 → 智能群助手 → 添加机器人 → **自定义**（Webhook 接入）：

| 安全设置 | 填写方式 |
|---|---|
| 加签 | 填入 `SEC` 开头的密钥 |
| 自定义关键词 | 填入关键词，推送时会自动加在消息标题前 |
| IP 白名单 | 把 NAS 的内网 IP 加入白名单 |

### 摄像头画面

推送时可附带打印机摄像头画面（快照内嵌 + 短视频链接）：

- 需要打印机开启局域网模式且固件支持 RTSP（X1 全系支持；P1 / A1 系列需较新固件）
- 快照与视频保存在 NAS 的 `data/media/` 下，由服务托管，链接形如 `http://NAS的IP:8787/media/xxx.jpg`
- **群成员与 NAS 在同一局域网时**才能看到图片和打开视频；外网访问不到（可自行配合内网穿透解决）
- 每台设备各自抓取自己的 RTSP 流；页面每行的「测试」按钮可直接验证并预览画面

### 通知规则

| 开关 | 默认 | 说明 |
|---|---|---|
| 通知总开关 | 开 | 关闭后仅记录事件、不推送 |
| 开始打印 | 开 | 空闲 / 完成 / 失败 → 打印中 |
| 打印完成 | 开 | 含耗时统计 |
| 打印失败 | 开 | 含错误码 |
| 暂停 / 恢复 | 关 | |
| 打印中离线 | 开 | MQTT 断连且正在打印时提醒 |
| 进度节点推送 | 开 | 每推进 25% 推一次（可改 5–100） |

推送与否由下面三层一起决定，页面上的说明与这里一致：

1. **通知总开关**关闭后，监控事件都不推送（「测试钉钉推送」除外）
2. **事件勾选**是总闸。没勾的类型不会推送，时间段里再勾也不行
3. **推送时间段**是可选项。列表为空时不做时间过滤；一旦添加了时段，还要落在某个**已启用**、并且勾选了该事件的时段里才会推送

### 推送时间段

在「通知规则」下方可以添加最多 8 个时段，随「保存全部」写入 `data/config.json`。密钥输入框留空仍表示保持已保存的值，与时间段无关。

- 多个时段是**或**关系：命中任意一个就推，重叠不会连发多条
- 时段可以单独停用。全部停用时不会推送；把时段都删掉才会恢复全天推送
- 支持跨午夜。`22:00–07:00` 覆盖晚上 22:00 到次日 07:00（起止时刻那一分钟都算在内）。开始与结束相同（如 `08:00–08:00`）表示全天
- 星期可选，周一到周日对应勾选。不选任何一天则该时段不生效。跨午夜时按**当前这一分钟**所属的星期判断：只勾选周一的 `22:00–07:00`，包含周一 22:00–24:00 和周一 00:00–07:00，不包含周二凌晨
- 每个时段再勾一次要推的事件（开始 / 完成 / 失败 / 暂停 / 恢复 / 打印中离线 / 进度）。必须上方总闸和本时段都勾选
- 被时间段拦住时不推送、也不抓摄像头，事件日志会写「不在推送时间段内，已跳过」。打印机状态本身仍照常刷新。错过的进度节点不会在时段开始后补推
- 时间用**服务器本地时区**。Docker 镜像和 `docker-compose.yml` 都把 `TZ` 设为 `Asia/Shanghai`；要改时区就改这个环境变量（需系统里有对应的时区数据，镜像已安装 `tzdata`）
- 「测试钉钉推送」忽略总开关和时间段，用来确认机器人本身可用

## 工作原理

服务为每台已启动的设备建立独立的 MQTT over TLS（8883 端口，用户名 `bblp`，密码为访问码）连接，订阅 `device/<SN>/report` 主题，解析 `gcode_state`、`percent`、`layer_num`、`remaining_time`、`nozzle_temper` 等字段；状态变化时先看通知总开关、事件勾选和推送时间段，再按钉钉自定义机器人规范推送 markdown 消息（加签方式为 HMAC-SHA256），标题格式为「设备名称 + 事件」，例如 `P2S_1 开始打印`。版本号定义在 `app.py` 的 `__version__`，页面和 `/api/config`、`/api/status` 都读这一处。

适配拓竹 X1 / P1 / A1 全系列（含 A1 mini），需开启局域网模式。

## 目录结构

```
├── app.py               # 服务主体（FastAPI + paho-mqtt + 钉钉推送 + RTSP 抓流）
├── static/index.html    # Web 配置与状态页
├── tests/test_schedule.py  # 推送时间段匹配测试
├── Dockerfile           # 内含 ffmpeg 与 tzdata，默认时区 Asia/Shanghai
├── docker-compose.yml
└── data/                # 运行时生成，保存 config.json 与 media/ 画面文件
```
