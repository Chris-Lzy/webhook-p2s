# webhook-p2s — 拓竹打印机监控通知服务

轻量级拓竹（Bambu Lab）打印机局域网监控服务（当前版本 **2.2.1**）：通过打印机本地 MQTT 获取打印状态，把开始 / 完成 / 失败 / 暂停 / 恢复 / 进度推送到**钉钉**、**企业微信**和**飞书**。自 2.1.0 起在实时监控之上，用打印机自己报上来的数据做耗材库、装填记录、任务归档和材料成本，不读取 Bambu Studio 的本地工程或缓存。2.1.1 修正三件事：槽位重复上报后不再丢掉耗材关联，补上单价会重算成本；同一耗材编号的多槽按颜色记账；耗材历史里「更新单价」只显示一次。2.2.0 修正进度节点推送：打印状态不变时也按进度步长正常推送（此前状态未切换时进度更新会被跳过）；推送正文与状态面板新增「剩余时间（分钟）」和「预计完成（北京时间）」。2.2.1 修正打印耗时：新的一单（包括先进入准备再开打，或上一单的 `gcode_start_time` 还留在报文里）会重新计时。1%、中途进度和完成推送的耗时都按当前任务计算，状态列的已用时间与推送一致。

自带 Web 控制台与局域网扫描，Docker 一键部署。访问码只用来连接打印机（MQTT / FTPS / 摄像头），不会写进日志或前端回包。

## 功能特性

- **最多 1000 台设备**：动态添加、删除；按名称 / IP / 序列号 / 任务名 / 中文状态（如「打印中」「失败」）过滤。
- **局域网扫描**：SSDP 组播/广播 + 网段 8883 端口探测，一键加入列表。
- **多渠道推送**：钉钉（Markdown，可内嵌快照）、企业微信（Markdown，不能显示图片，只附链接）、飞书（富文本，加粗和链接；自定义机器人不能直接展示外链图片）。各渠道独立开关和测试；「一键测试推送」会发给所有已启用渠道。
- **实时状态**：连接状态、进度、当前层/总层、剩余时间（分钟）、预计完成（北京时间）、喷嘴温度、热床温度、任务名、已用时间。鼠标悬停在状态上可以看到完整摘要；推送正文同样带剩余分钟数与预计完成时刻。
- **摄像头**：X1 / H2 常见 RTSP `322`；P1 / A1 常见端口 `6000`。P2S 上 RTSP 可能被固件关闭。抓图失败只少一张图，不影响监控和任务归档。
- **推送时间段**：最多 8 段，可跨午夜、按星期、按事件。未添加时段时全天推送。低余量告警同样受总开关和时间段约束。
- **事件日志**：最近 100 条。被时间段拦住的推送记为「已跳过」。
- **耗材库**：手工录入品牌、材料、颜色、净重（克）、单价（**每千克**，默认人民币 CNY）、购买日期和备注。官方 RFID 料盘在 AMS 上报新的 `tag_uid` + `tray_uuid` 时自动建档，并带上材料、颜色、直径、标称重量、温度和烘干提示，通常只需要补单价。没有芯片的料盘绑定到打印机槽位，包括外挂 `vt_tray`。
- **装填记录**：打印机不提供装填时间。服务在线时，若槽位从空变为有料，或 `tag_uid` / `tray_uuid` 变化，就记下时间、打印机、槽位和耗材身份。离线期间的换料无法补记真实时间。
- **任务归档**：开始和结束时记录打印机、模型名、起止时间、层数、用时、用过的料盘和克数（有米数也记）。能从打印机拿到预览图或摄像头静帧就存下来。
- **成本**：材料成本 = Σ(克数 / 1000 × 每千克单价)。缺单价显示「待补全」，而不是 0；补上单价后重算。电费和人工是可选项：手动的元/小时 × 打印时长。同一模型多次打印会汇总次数、总克数、总成本，以及已算清任务的平均 / 最低 / 最高成本。
- **报表**：按模型、耗材/标签、材料、颜色、打印机、日/月汇总，并能从耗材追到模型、从模型追到耗材。
- **低余量告警**：阈值可配（默认 10%）。`remain = -1` 表示打印机不知道剩余，不告警，也不拿来估算克数。

## 快速开始

```bash
git clone https://github.com/Chris-Lzy/webhook-p2s.git
cd webhook-p2s
docker compose up -d --build
```

浏览器打开 `http://NAS的IP:8787`。页顶可以在「监控 / 耗材库 / 装填 / 任务 / 报表」之间切换。

已有 2.0.0 的 `data/config.json` 会照常加载。第一次启动时自动创建耗材库数据库，不需要手工迁移。

## 配置与使用指南

### 1. 打印机

1. 打印机屏幕：**设置 → 局域网 / LAN 模式**，记下访问码。
2. 打印机和部署这套服务的机器在同一局域网。
3. 点「扫描局域网」或「添加设备」，填好 IP、序列号、访问码后保存并启动。

访问码留空保存表示不改原来的值。页面回读配置时不会把访问码、Webhook、加签密钥发回浏览器。

### 2. 推送渠道

| 渠道 | 配置 | 快照 |
|---|---|---|
| 钉钉群机器人 | Webhook、加签密钥、自定义关键词 | Markdown 可以内嵌图片 |
| 企业微信 | Webhook | Markdown **不能**显示图片，消息里只有链接 |
| 飞书 | Webhook、加签密钥 | 富文本可以加粗和放链接；外链图片不能直接渲染 |

各渠道开关独立。通知总开关关掉后，正常事件和低余量告警都只记日志、不推送。测试按钮不受总开关和时间段限制。

### 3. 通知规则与时间段

| 开关 | 默认 | 说明 |
|---|---|---|
| 通知总开关 | 开 | 关闭后不推送 |
| 开始 / 完成 / 失败 | 开 | 完成消息带耗时，失败消息带错误码 |
| 暂停 / 恢复 | 关 | |
| 打印中离线 | 开 | MQTT 断开且正在打印 |
| 进度节点 | 每 25% | 可改 |
| 低余量 | 开，阈值 10% | 在「耗材与成本」里改；时间段里可以单独取消「余量」 |

时间段最多 8 个，命中任意一个且勾了对应事件才推送。支持 `22:00–07:00` 这种跨午夜。不添加时间段则全天推送。从 2.0.0 升上来的旧时间段，如果当时没有「余量」这一项，默认视为允许低余量告警，可以再关掉。

### 4. 耗材、用量和成本

单价单位是**每千克**。材料成本 = 克数 / 1000 × 单价。币种默认 CNY，不做汇率换算，请让所有料盘使用同一种货币。

用量按下面的顺序取值：

1. **文件（精确）**：用访问码登录打印机 FTPS（用户 `bblp`，隐式 TLS 端口 `990`），下载任务的 3mf 或 gcode。3mf 是 zip，切片信息通常在 `Metadata/slice_info.config`（`used_g` / `used_m`），预览图通常是 `Metadata/plate_*.png`。数据连接会复用 TLS 会话，否则 vsftpd 会返回 `522 SSL connection failed: session reuse required`。
2. **估算**：文件拿不到时，用 `标称重量 × (开始余量% − 结束余量%) / 100`。只统计余量下降的槽，以及当前正在用的那一槽。
3. **未知**：余量任一端是 `-1` 或缺失，或者没有标称重量。这种行不会被填成 0。

电费、人工留空表示这单不算这两项。改费率或补单价后，已归档任务会按新价格重算。

## 数据放在哪里

Compose 把宿主机的 `./data` 挂到容器 `/app/data`（可用环境变量 `DATA_DIR` 改容器内路径）。这里面现在有：

| 路径 | 内容 |
|---|---|
| `data/config.json` | 打印机、推送渠道、时间段、摄像头、低余量阈值和费率。不含任务和耗材流水 |
| `data/inventory.db` | 耗材、装填、任务、用量（SQLite） |
| `data/archive/` | 任务预览图和摄像头静帧 |
| `data/media/` | 推送时抓的实时画面，仍只保留最近约 100 个文件 |

重建容器不会丢掉这些文件，只要卷还在。

归档图片默认保留 **90 天**且最多 **400 张**，在「耗材与成本」里改。填 0 表示关闭对应的那一条限制。超限的文件会删掉，任务记录还在，只是图片列变成空的。

没有新增必填环境变量。时区仍然建议 `TZ=Asia/Shanghai`，时间段和按日/按月报表都按容器本地时区计算。服务端口默认 `8787`（`PORT`）。

## 已知限制

- **FTPS 目录可能是空的。** 在一台云模式的 P2S（型号 N7，固件 01.03.00.00）上，FTPS 能登录（vsftpd 3.0.5），但 chroot 里只有 `.` 和 `..`，访问 `/data`、`/cache` 返回 550。MQTT 仍会报 `gcode_file=/data/Metadata/plate_1.gcode` 且 `sdcard=false`。这会被当成固件/安全限制：任务照常归档，用量改走余量估算或标成未知。
- **装填时间只在本服务在线时有效。** 离线期间换料，重新连上后的第一次看见只作为基线，不会伪造一条装填记录。
- **`remain = -1` 是未知，不是 0%。** 官方 PETG 也可能带着合法标签却报 -1。这种料不估算克数，也不触发低余量告警。
- **摄像头没有统一协议。** 抓不到静帧时任务记录仍然保存。
- **企业微信不能在 Markdown 里显示图片，飞书自定义机器人也不能直接嵌外链图。** 这两路会给出链接。钉钉可以显示图片。
- **电费和人工不是电表读数**，只是费率乘以本服务观察到的打印时长。服务中途才启动时，开始时间会标明不完整。
- 不读取 Bambu Studio 工程文件，也不扫描电脑上的切片缓存。

## 架构

- 每台已启用的打印机一个 MQTT over TLS 客户端（端口 8883，用户名 `bblp`，密码为访问码），订阅 `device/<SN>/report`。
- AMS / 外挂料盘字段来自 `print.ams` 和 `vt_tray`。空槽在 P2S + AMS 2 Pro 上通常只有 `id` 和 `state=9`；装了官方料的槽常见 `state=11`，并带 `tray_type`、`tray_color`、`tray_weight`、`remain`、`tag_uid`、`tray_uuid` 等。其他系列缺字段时会跳过，不会编造。
- 扫描器向 `239.255.255.250:2021` 发 SSDP `M-SEARCH`，并并发探测 8883。
- 任务文件走 FTPS 990；摄像头先试 RTSP 322，再试 6000 上的几种 HTTP 快照地址。
